## 三个必须书面回答的问题

### 1. `pnpm dev:once` 与 `paperclipai run` 是否是同一条装配路径

**不是完整等价路径。** 两者最终都可能加载 `server/src/index.ts`，但入口契约不同：

- `paperclipai run` 先执行前台服务冲突检查、配置解析、环境文件加载、worktree seed、doctor、运行时信息登记，并在满足条件时生成 bootstrap invite；本轮在 doctor 阶段被挡住。
- `pnpm dev:once` 先由 `scripts/dev-runner.ts` 构建 runner TypeScript/必要的 native binary、构建 plugin SDK、做迁移预检、登记 dev service，再 spawn `pnpm --filter @paperclipai/server dev`。

“最终 server 模块相同”不能推出“生产入口装配等价”；启动前 Gate、生命周期登记与失败面均不同。

### 2. 第 1 步的“能启动”如何判

本席判定为：**开发路径能启动；默认生产入口未验证，且本轮实测为失败，不计入默认入口交付。** 因本席唯一职责是默认生产入口放行，所以本单结论是“不放行”，不是“有条件放行”。

### 3. `paperclip-runnerd` 算已交付还是已合并未激活

判定：**构建产物已交付；运行接线属于已合并未激活。** 理由：binary 存在、摘要可读、构建日志为 0；但 `.server.log` 没有 runnerd 启动证据，本轮及执行记录均没有 agent heartbeat 触发该 binary。产物存在不等于默认路径调用过。
