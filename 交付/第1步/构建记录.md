### 0.3 ⚠️ 对上游规格的一条更正（不改规格文件，按转派链上报）

任务书步骤 0 与验收单 AC-04 的取证说明都写：「席位手上的 API 凭证读不到正式实例的公司清单——`GET /api/companies` 返回 `{"error":"Board access required"}`，因此基线只能从界面上看」。

**本席实测结论与此不同，且更宽松**：

```sh
# 不带任何 Authorization 头 → 返回完整的 14 家公司清单
curl -s http://127.0.0.1:3100/api/companies

# 带席位自己的 API key → 反而被拒
curl -s -H "Authorization: Bearer $PAPERCLIP_API_KEY" http://127.0.0.1:3100/api/companies
{"error":"Board access required"}
```

原因：正式实例的 `/api/health` 报 `"deploymentMode":"local_trusted"`，本机回环的匿名请求被当作可信访问；而带上席位 key 后按席位权限判定，席位无 board 权限故被拒。

**影响**：AC-04 的基线与阴性对照都可以用命令取证，不必依赖界面截图或 board 代劳，取证强度更高。本记录的基线即用此法取得。

**处理**：这是对规格的**补充更正**，属上游产物（`任务书.md` / `验收单.md`）的内容。按并发纪律，本席**不修改那两份文件**，只在此记录并在 TOK-157 评论里沿转派链上报。验收席做 AC-04 时可直接用上面那条不带 Authorization 头的 `curl`。
