# TOK-226 B3 接口证据

执行席：开发部·后端实现席。对照经理评论 `588c32ac`。
本文件只记本轮针对系统 notice 与审计 action 的请求/响应形状；HTTP 错误汉化证据仍见 `后端交付.md` §四。

## 1. 系统 notice 写入形状（异步持久化，不随请求语言变化）

调用链：`buildSuccessfulRunHandoffRequiredNotice` → `issues.addComment({ authorType: "system", presentation, metadata })`。
`addComment` 用 `issueCommentPresentationSchema.parse`；读取再用同一 schema `.catch(null)`。

### 1.1 正常：缺少处置 notice

输入：成功运行且任务仍为 `in_progress`，无有效处置。

期望：`presentation.title` 为英文常量，metadata 带机器码。

实际（契约测试 2026-09-27，vitest exit 0）：

```json
{
  "body": "Paperclip needs a disposition before this issue can continue.",
  "presentation": {
    "kind": "system_notice",
    "tone": "warning",
    "title": "Missing issue disposition",
    "detailsDefaultOpen": false
  },
  "metadata": {
    "version": 1,
    "sourceRunId": "22222222-2222-4222-8222-222222222222",
    "sections": [
      {
        "title": "Required action",
        "rows": [
          { "type": "issue_link", "label": "Source issue", "identifier": "PAP-1" },
          { "type": "agent_link", "label": "Assignee", "name": "CodexCoder" },
          { "type": "key_value", "label": "Missing disposition", "value": "clear_next_step" }
        ]
      },
      {
        "title": "Run evidence",
        "rows": [
          { "type": "key_value", "label": "Normalized cause", "value": "successful_run_missing_state" }
        ]
      }
    ]
  }
}
```

通过。中文界面应映射 `title`，不要改库里的英文。

### 1.2 正常：恢复耗尽 notice

实际：

```json
{
  "body": "Paperclip could not resolve this issue's missing disposition automatically. The source assignment is unchanged and a board decision is required.",
  "presentation": {
    "kind": "system_notice",
    "tone": "danger",
    "title": "Missing disposition recovery blocked",
    "detailsDefaultOpen": false
  }
}
```

`Normalized cause` 仍为 `successful_run_missing_state`。通过。

### 1.3 错误：给 presentation 加 `code`（本单不能改 shared schema）

输入：

```json
{
  "kind": "system_notice",
  "tone": "warning",
  "title": "Missing issue disposition",
  "detailsDefaultOpen": false,
  "code": "missing_issue_disposition"
}
```

期望：schema `.strict()` 拒绝。

实际：`issueCommentPresentationSchema.parse(...)` 抛 Unrecognized key（vitest 断言 `/Unrecognized key/i`，exit 0）。

读取路径若硬塞该字段，`.catch(null)` 会把整段 presentation 变成 `null`。所以本轮不加新字段。

### 1.4 默认/英文模式

无 locale、或英文 UI：title/body 保持上述英文。构建函数不读 `X-Paperclip-Locale`。通过（断言 title/body 无汉字）。

## 2. 审计 `environment.lease_acquired`

### 2.1 正常：acquireForRun

输入：`environmentRunOrchestrator.acquireForRun({ companyId, selectedEnvironmentId, heartbeatRunId, agentId, issueId, ... })`。

期望：`logActivity` 的 `action` 为点分机器码。

实际（`environment-run-orchestrator.test.ts`，exit 0）：

```js
logActivity(db, {
  action: "environment.lease_acquired",
  entityType: "environment_lease",
  entityId: "lease-1",
  issueId: "issue-1",
  agentId: "agent-1",
  runId: "run-1",
})
```

通过。界面英语 `environment lease acquired` 来自前端把未收录 action 的 `.`/`_` 换成空格，不是服务端写了英文说明。

### 2.2 正常：releaseForRun

实际：`action: "environment.lease_released"`，`entityType: "environment_lease"`。通过。

### 2.3 列表接口形状（既有路由测试，action 原样回读）

`GET /api/companies/:companyId/activity` 与 `GET /api/companies/:companyId/audit/agent-actions` 的 item 含：

```json
{
  "action": "plugin.synced",
  "entityType": "company",
  "entityId": "company-1",
  "actorType": "plugin"
}
```

`action` / `entityType` 与落库值相同，服务端不做人话转换。`environment.lease_acquired` 走同一条路。

来源：`server/src/__tests__/activity-routes.test.ts`（`res.body.items[0].action === "plugin.synced"`）。
