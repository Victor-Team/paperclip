## 1. 系统 notice 写入形状（异步持久化，不随请求语言变化）

调用链：`buildSuccessfulRunHandoffRequiredNotice` → `issues.addComment({ authorType: "system", presentation, metadata })`。
`addComment` 用 `issueCommentPresentationSchema.parse`；读取再用同一 schema `.catch(null)`。

### 1.1 正常：缺少处置 notice

输入：成功运行且任务仍为 `in_progress`，无有效处置。

期望：`presentation.title` 为英文常量，metadata 带机器码。

实际（契约测试 2026-09-27，vitest exit 0）：

```json
{
  "body": "Paperclip needs a disposition before this issue can continue.",
  "presentation": {
    "kind": "system_notice",
    "tone": "warning",
    "title": "Missing issue disposition",
    "detailsDefaultOpen": false
  },
  "metadata": {
    "version": 1,
    "sourceRunId": "22222222-2222-4222-8222-222222222222",
    "sections": [
      {
        "title": "Required action",
        "rows": [
          { "type": "issue_link", "label": "Source issue", "identifier": "PAP-1" },
          { "type": "agent_link", "label": "Assignee", "name": "CodexCoder" },
          { "type": "key_value", "label": "Missing disposition", "value": "clear_next_step" }
        ]
      },
      {
        "title": "Run evidence",
        "rows": [
          { "type": "key_value", "label": "Normalized cause", "value": "successful_run_missing_state" }
        ]

```

通过。中文界面应映射 `title`，不要改库里的英文。

### 1.2 正常：恢复耗尽 notice

实际：

```json
{
  "body": "Paperclip could not resolve this issue's missing disposition automatically. The source assignment is unchanged and a board decision is required.",
  "presentation": {
    "kind": "system_notice",
    "tone": "danger",
    "title": "Missing disposition recovery blocked",
    "detailsDefaultOpen": false
  }
}
```

`Normalized cause` 仍为 `successful_run_missing_state`。通过。

### 1.3 错误：给 presentation 加 `code`（本单不能改 shared schema）

输入：

```json
{
  "kind": "system_notice",
  "tone": "warning",
  "title": "Missing issue disposition",
  "detailsDefaultOpen": false,
  "code": "missing_issue_disposition"
}
```

期望：schema `.strict()` 拒绝。

实际：`issueCommentPresentationSchema.parse(...)` 抛 Unrecognized key（vitest 断言 `/Unrecognized key/i`，exit 0）。

读取路径若硬塞该字段，`.catch(null)` 会把整段 presentation 变成 `null`。所以本轮不加新字段。

### 1.4 默认/英文模式

无 locale、或英文 UI：title/body 保持上述英文。构建函数不读 `X-Paperclip-Locale`。通过（断言 title/body 无汉字）。

## 2. 审计 `environment.lease_acquired`

### 2.1 正常：acquireForRun

输入：`environmentRunOrchestrator.acquireForRun({ companyId, selectedEnvironmentId, heartbeatRunId, agentId, issueId, ... })`。

期望：`logActivity` 的 `action` 为点分机器码。

### 2.3 列表接口形状（既有路由测试，action 原样回读）

`GET /api/companies/:companyId/activity` 与 `GET /api/companies/:companyId/audit/agent-actions` 的 item 含：

```json
{
  "action": "plugin.synced",
  "entityType": "company",
  "entityId": "company-1",
  "actorType": "plugin"
}
```

`action` / `entityType` 与落库值相同，服务端不做人话转换。`environment.lease_acquired` 走同一条路。

来源：`server/src/__tests__/activity-routes.test.ts`（`res.body.items[0].action === "plugin.synced"`）。

## 5. 第二轮 B3：stranded-notice 构造器契约（经理评论 `57759527`）

异步写入仍为英文常量，不读请求语言。下列为 `buildStrandedRecoveryEscalationNotice` 实测形状。

### 5.1 截图三句：默认分支（无 seed、无 owner、无 sourceRun）

输入：`recoveryActionId` UUID，`recoveryOwner=null`，`sourceRun=null`。

期望：标题 `Automatic recovery blocked`；`Recovery owner` 为 `Board decision required`；`Next action` 为固定标签 + 无 owner 模板。

实际（契约测试 2026-09-27，vitest exit 0）：

```json
{
  "body": "Paperclip could not restore a live execution path for this issue automatically. Moving it to `blocked` so it is visible for intervention.",
  "presentation": {
    "kind": "system_notice",
    "tone": "danger",
    "title": "Automatic recovery blocked",
    "detailsDefaultOpen": false
  },
  "metadata": {
    "version": 1,
    "sourceRunId": null,
    "sections": [
      {
        "title": "Recovery",
        "rows": [
          { "type": "key_value", "label": "Recovery action", "value": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa" },
          { "type": "key_value", "label": "Recovery owner", "value": "Board decision required" },
          { "type": "key_value", "label": "Next action", "value": "Inspect the evidence, then retry the original owner, explicitly reassign, repair the execution path, or record an intentional resolution" }
        ]
      }
    ]
  }
}
```

### 5.2 正常：有 owner 时 Recovery owner 是 agent_link

`recoveryOwner={ id, name }` 时该行 `type=agent_link`，value 不再是 `Board decision required`；`Next action` 换成有 owner 模板。UUID / 人名原样。

### 5.3 正常：workspace 扫描 / 运行 errorCode / recoveryCause

| 输入 | `presentation.title` | 机器码所在 |
|---|---|---|
| `sourceRun.errorCode=workspace_git_scan_timeout`（及其它 4 个 scan 码） | 扫描标题表 | metadata `Failure code` = 该 errorCode |
| `sourceRun.errorCode=provider_quota` / `claude_auth_required` / `acpx_auth_required` | 对应 Error: … 标题 | 同上 |
| 无 seed，`recoveryCause=workspace_validation_failed` 等三码 | cause 标题表 | 标题即闭集英文；cause 本身不另写一行 |
| 未收录 `errorCode=process_lost` + seed「No live execution path」 | 仍为 seed 标题 | `Failure code=process_lost` |

### 5.4 配置不完整三分支

| reason | title | 动态参数 |
|---|---|---|
| 缺省 / 其它 | `Configuration incomplete` | 无 |
| `ai_connection_unavailable` | `AI connection needs attention` | 无（正文与 Next action 为固定英文） |
| `sandbox_provider_plugin_not_ready` | `Configuration incomplete` | 正文反引号内 `pluginKey`、`pluginStatus` 保持机器值 |

### 5.5 错误：presentation 仍不能加 `code`

与 §1.3 相同。`issueCommentPresentationSchema` 为 `.strict()`。本轮不加新 JSON 字段。
