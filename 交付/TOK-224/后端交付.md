## 一、结论摘要

服务端在简体中文界面实际显示的英文提示，几乎全部经由**一条路径**进入界面：
HTTP 响应顶层 `error` 字符串 → 前端 `ApiError.message` 原样渲染。

**本轮返工针对驳回点**：上一版把约 2,000 种未入词表的固定错误以「低频」为由保持英文，
而顶层 `error` 会原样上屏，无法证明中文界面没有英文提示。

本轮性质保证：

> 对解析为 zh-CN 的请求，顶层 `error` 里可达的服务端固定英文文案
> **不会以英文出现在界面上**。未入词表的英文散文改为状态类中文
> （如 404→「未找到」），原文放到同级 `errorOriginal` 保留排障信息。
> 不盲翻长尾。技术标识与数据载荷按下列例外清单逐类保留原文。

机制仍是单点 `res.json` 包装，不改业务代码：

1. **语言解析**（`server/src/i18n/locale.ts`）：`X-Paperclip-Locale` →
   `Accept-Language`（RFC q 值）→ 默认 `en`。本轮按 `X-Paperclip-Locale: zh-CN`
   验证契约（前端接线归 TOK-225）。
2. **查表**（`localizeServerMessage`）：精确词表 → 锚定模板 → 技术标识/数据
   原样通过 → 无 ASCII 散文原样通过 → **状态类中文兜底**。
3. **HTTP 层**：仅改写顶层 `error`；兜底时附加 `errorOriginal`；`code` /
   `details` / 成功载荷不动。默认无头请求逐字节英文（中间件不包装）。

## 三、处理规则与例外清单

### 3.1 质量路径（精确中文）

权威清单 = `server/src/i18n/zh-cn-messages.ts`：120 条整串精确 + 12 条锚定模板。
术语沿用前端 zh-CN.json（issue→任务、agent→智能体、secret→机密…）。
模板捕获组（ID、名称、权限串如 `tools:manage_connections`）逐字保留。

### 3.2 保证路径（未收录英文散文）

未入词表、且被判定为英文散文的顶层 `error`，按 HTTP 状态改写为：

| 状态 | 界面 `error` |
|---|---|
| 400 | 请求无效 |
| 401 | 未授权 |
| 403 | 禁止访问 |
| 404 | 未找到 |
| 408 | 请求超时 |
| 409 | 请求冲突 |
| 410 | 资源已不存在 |
| 412 | 前提条件失败 |
| 413 | 请求体过大 |
| 415 | 不支持的媒体类型 |
| 416 | 请求的范围无法满足 |
| 422 | 请求无法处理 |
| 429 | 请求过于频繁 |
| 500 / 其他 5xx | 服务器内部错误 |
| 501 | 服务器不支持此功能 |
| 502 | 网关错误 |
| 503 | 服务不可用 |
| 504 | 网关超时 |
| 其余 4xx / 缺省 | 请求失败 |

同时附加 `errorOriginal`（原文英文），排障信息留在响应体，不进入 `ApiError.message`。
**不盲翻**长尾句子，避免把实体词、字段名、用户数据译错。

### 3.3 例外清单（zh-CN 请求下 `error` 仍可能是原文）

以下类别**不是**用户可读的固定英文文案，保留原文并列出理由。
每一类都有测试或 HTTP 探针覆盖。

| # | 例外 | 判定 | 理由 | 证据 |
|---|---|---|---|---|
| E1 | 技术标识整串 | 含分隔符的 snake/kebab/colon 键（`dev_server_supervisor_unavailable`、`tools:manage_connections`）、ALL_CAPS 码（`ECONNREFUSED`）、UUID | 机器码/能力标识，译成中文会丢掉排障所需的标识本身 | 探针 #8；`translate.test.ts` technical tokens |
| E2 | 数据载荷整串 | 绝对/相对路径、`http(s)://` URL、JSON 对象/数组文本 | 数据内容，任务红线禁止盲译 | `translate.test.ts` data payloads |
| E3 | 非英文散文 | 无连续两个 ASCII 字母：纯中文、数字、符号 | 没有英文文案可译 | 同测试：`任务不存在`、`42` |
| E4 | 空字符串 | `error === ""` | 无文案 | `translate.test.ts` empty string |
| E5 | 结构化兄弟字段 | `code`、`reason`、`details`、`remediation`、嵌套对象 | 机器契约 / 库生成 | 探针 #9：`details[].message` 仍为英文 |
| E6 | 成功载荷 | 无顶层字符串 `error` | 不是错误提示 | 探针 #1/#2：`{"ok":true,"name":"ANC 测试公司"}` 不变 |
| E7 | 默认语言 / 非简体 | 无语言头、`X-Paperclip-Locale: en`、裸 `zh-TW`/`zh-Hant` | 历史默认路径；简体词表不对繁体冒充 | 探针 #3/#5；locale 测试 |
| E8 | 路径 4–9 的非 HTTP-error 面 | SSE 载荷、DB 存储 runner 文本、webhook、health、HTML | 见 §二；不是「服务端固定错误文案 → ApiError.message」 | 排查表 |

**单字母小写英文单词不是技术标识**（必须带分隔符）。例如整串 `forbidden` 在 403 下会变成「禁止访问」，不会因为像标识而漏网。

**不作为例外的**：一切未入词表、带英文散文的可达固定错误——上一版约 2,000 种长尾。
它们现在走 §3.2，界面 `error` 为中文。

### 4.2 实际 HTTP 响应（curl 原文）

探针：临时 Express 应用注册**本分支真实中间件** `localizeErrorResponses()`，
错误出口与生产相同（`HttpError` → `res.status(status).json({ error: message })`）。
`curl -sS -D -` 打到 `127.0.0.1:<ephemeral>`。跑完即关，未部署、未碰 3100 正式实例。

契约头一律用经理指定的 `X-Paperclip-Locale: zh-CN`（#10 另测 Accept-Language）。

**#1 正常路径 无语言头** → 200

```
{"ok":true,"name":"ANC 测试公司"}
```

**#2 正常路径 `X-Paperclip-Locale: zh-CN`** → 200（与 #1 逐字节相同）

```
{"ok":true,"name":"ANC 测试公司"}
```

**#3 已知错误 无语言头** → 404

```
{"error":"Issue not found"}
```

**#4 已知错误 `X-Paperclip-Locale: zh-CN`** → 404

```
{"error":"未找到任务"}
```

**#5 未收录错误 无语言头** → 404

```
{"error":"Widget not found"}
```

**#6 未收录错误 `X-Paperclip-Locale: zh-CN`** → 404
（界面字段为中文，英文不在 `error` 里）

```

```

**#7 未收录 409 `X-Paperclip-Locale: zh-CN`** → 409

```
{"error":"请求冲突","errorOriginal":"Widget already claimed by another process"}
```

**#8 技术标识 `X-Paperclip-Locale: zh-CN`** → 503（例外 E1）

```
{"error":"dev_server_supervisor_unavailable"}
```

**#9 校验错误 + details `X-Paperclip-Locale: zh-CN`** → 400
（顶层已译；`details[].message` 库生成技术文本保留，例外 E5）


**#10 已知错误 `Accept-Language: zh-CN,zh;q=0.9`** → 404

```
{"error":"未找到任务"}
```

### 4.3 与界面的连接

- 浏览器语言为简体中文时，`fetch` 自动带 `Accept-Language: zh-CN`，服务端
  `error` 即为中文（精确或状态类），toast 不再出现未收录英文固定文案。
- 界面语言切换器接入 `X-Paperclip-Locale` 仍归 TOK-225；本席已按该头验证。
- `errorOriginal` 仅在兜底时出现。当前前端只渲染 `error`，不会把原文送上屏。
  网络面板 / 日志可看到原文以便排障。

## 五、前端适配契约（交经理整合，本席未改前端）

TOK-225 负责在 `ui/src/api/client.ts` 的 `request()` 加：

```ts
headers.set("X-Paperclip-Locale", <当前 i18next 语言，如 "zh-CN">);
```

本轮验证：只发 `X-Paperclip-Locale: zh-CN`、不发 Accept-Language，已知错误与
未收录错误均按上面 #4/#6 返回中文。

可选后续（非本单）：若 UI 要把兜底的「未找到」展开成原文，读 `errorOriginal`。
现在不加也不影响「中文界面不显示英文固定错误」这一性质。
