## 一、两条代码强制约束（实查证据）

### 约束 A：语言写死在 `en`，没有任何切换入口

`ui/src/i18n/index.ts`：

```ts
const i18nextOptions: InitOptions = {
  lng: DEFAULT_LOCALE,        // ← "en"
  fallbackLng: DEFAULT_LOCALE,
  ...
};
```

`ui/src/i18n/locales.ts:5`：`export const DEFAULT_LOCALE = "en" as const;`

全仓 `grep changeLanguage` → `ui/src` 下**无任何调用**（只有 `index.ts`/`locales.ts` 里
`DEFAULT_LOCALE` 自身的定义与引用）。没有 LanguageDetector，没有语言切换器。

**后果**：只改页面 `.tsx` ＋ `zh-CN.json`，界面**依然显示英文**。
方案 v1 的验收判据「乙.1 起服务后页面真显示中文」在 v1 的改动面下**按构造就不可能通过**。
第 1 步栽的就是「模块都好、默认入口从未验证」，这次是同一类坑的另一面：判据与改动面对不上。

### 约束 B：40 个语言文件的键集必须与 `en.json` 逐字相同

`ui/src/i18n/locales.ts` 在模块加载时对**每一个**语言文件跑
`assertValidLocaleMessages(messages)`；`ui/src/i18n/locale-validation.ts`
的 `validateNode` 同时拒绝 **missing keys** 和 **extra keys**：

```ts
for (const key of missingKeys) errors.push(`${...} is missing`);
for (const key of extraKeys)   errors.push(`${...} is not defined in English`);
```

上游自己的测试已经锁死这条：`ui/src/i18n/locale-validation.test.ts:21`
`it("rejects missing and extra nested keys", ...)`，断言文本含
`"app.noCompanies.newCompany is missing"` 与 `"app.noCompanies.unexpected is not defined in English"`。

现状：`ui/src/i18n/locales/` 下 **40 个** `.json`（不是描述里写的 41），
每个都只有 `app.noCompanies` 下的 3 个键，键集完全一致。

**后果**（两个方向都是死路）：
- 只往 `zh-CN.json` 加键 → 对 `en.json` 而言是 extra key → **抛异常，整个界面起不来**；
- 往 `en.json` ＋ `zh-CN.json` 加键 → 其余 38 个语言文件变成 missing key → **同样抛异常**。

所以每加 N 个键，**40 个语言文件都要同步加这 N 个键**（非中英语言填英文原文占位即可，
校验只比对键集与占位符，不比对是否真翻译）。这一步是机械的，可脚本化，一条
`git checkout -- ui/src/i18n/locales/` 全撤。

## 二、更正后的试点改动面

| 文件 | 改什么 | 性质 |
|---|---|---|
| 1 个页面 `.tsx` | 该页面的字面量换成 `t()` 调用 | 人工 |
| `ui/src/i18n/locales/en.json` | 新增该页面的 N 个键（英文原文） | 人工 |
| `ui/src/i18n/locales/zh-CN.json` | 新增同样 N 个键（中文，取自词表＋就地译） | 人工 |
| 其余 38 个 `locales/*.json` | 新增同样 N 个键，值填英文原文占位 | **脚本机械生成** |
| `ui/src/i18n/index.ts` | 加约 5 行：允许用 `?lng=` 或 `localStorage` 选语言；**默认仍是 `en`** | 人工 |

**合计 42 个文件**，其中 38 个是脚本生成的占位。回滚仍是一条命令：
`git checkout -- ui/src/pages/<页面>.tsx ui/src/i18n/`。

### 为什么选「加 5 行读 `?lng=`」而不是别的
- 装 `i18next-browser-languagedetector` → **引入新依赖，红线禁止**；
- 把 `DEFAULT_LOCALE` 改成 `zh-CN` → 这是**改产品默认语言**，属于改公司产品形态，不该夹在试点里偷偷做；
- 加语言切换器 UI → 试点范围外，改动面还要涨。

保持默认 `en`、只开一个 `?lng=zh-CN` 的旁路，是能让「乙.1 截图证明页面真显示中文」
成立的**最小**改动，且不改变任何现有用户看到的东西。

## 三、试点页面选型

### 选型规则（按此排序，执行席照这个顺序试）
1. **路由不被 `HiddenSettingsPageGate` 守卫** —— 被守卫的页面在隔离实例里可能根本打不开，试点会因为无关原因失败；
2. **没有 `.production.tsx` 双胞胎** —— 有双胞胎则存在两条渲染路径，「改 1 个 `.tsx`」是假的；
3. **自渲染文案占比高** —— 页面可见文字要大部分来自这一个文件，否则截图里自己的中文会被子组件的英文淹没；
4. **规模适中**：词表条目 30～60 条，文件 500～1000 行；
5. **长尾占比 50%～80%** —— 词表已译的和就地译的**两条路都要被试到**。

### 数据（从 `交付/第2步/词表.md` 机械统计得出）

| 页面 | 词表条目 | 其中长尾（全表仅出现 1 次） | 文件行数 | 路由 | 守卫 | 双胞胎 |
|---|---|---|---|---|---|---|
| **`ui/src/pages/Search.tsx`（主选）** | 36 | 25（69%） | 922 | `/search` | 无 | 无 |
| `ui/src/pages/Dashboard.tsx`（备选） | 32 | 17（53%） | 561 | `/dashboard` | 无 | 无 |

**主选 `Search.tsx` 的理由**：它引入的子组件里，`@/components/ui/*`（tabs、input、button、
skeleton、badge）都是**无文案的样式原语**，页面可见文字集中在 `Search.tsx` 自己；
`Dashboard.tsx` 则引入 `MetricCard`、`EmptyState`、`ActivityRow`、`ActivityCharts`、
`InlineBanner` 等一串**自带文案**的组件，截图里大半英文不归试点文件管，判据不好判。

**决策规则**：执行席先试主选。若实测 `/search` 在隔离实例里打不开、或空态没有可见文案，
换备选 `Dashboard.tsx`，并在交付里写明实测到的原因（不许无声换）。

v1 写的是「该页面**无残留英文**」。页面由多个文件组合渲染，只改 1 个 `.tsx` 时
这条**永远不可能满足**——共用侧栏、顶栏、子组件的英文都还在。判据一交出去就是必判不过。

改成**可机械计数**的写法：

## 七、给实施子单的交接包备忘（批准后照抄进子单）

这四条是执行席最容易踩、验收席最容易漏的，**建子单时必须原样写进交接包**：

1. 🔴 **占位符必须原样保留。** `locale-validation.ts` 的 `validateString` 要求中文串里的
   `{{变量名}}` 与英文**逐字相同**（数量、名字、排序后比对），且**不允许出现英文里没有的 URL**。
   词表和术语表里的中文可能已经把 `{{var}}` 改写或丢了。凡英文含 `{{…}}` 的串，
   中文必须原样保留同名占位符，否则启动即抛异常。
2. 🔴 **`?lng=` 读到的值要原样是 `zh-CN`**（i18next resources 的键就是这个，来自文件名）。
   不许"顺手"做小写化、去区域码、或映射成 `zh`——那样查不到资源，静默回落英文，
   会被误判成接线失败。
3. **长度上限**：中文串长度不得超过 `min(2000, max(英文长度×4+64, 英文长度+128))`，超了抛异常。
   中文通常比英文短，一般不会触发，但超长描述类文案要留意。
4. **38 个占位文件的变更是预期的，不是越界。** 验收席按甲.1 数改动面时，
   `ui/src/i18n/locales/` 下 40 个 `.json` 全部出现在 `git status` 里属正常；
   越界的定义是**出现了 `ui/src/pages/<选中页面>.tsx`、`ui/src/i18n/` 之外的任何文件**。
